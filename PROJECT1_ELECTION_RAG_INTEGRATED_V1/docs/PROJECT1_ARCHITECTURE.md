# 프로젝트 1 통합 아키텍처 V1

## 설계 원칙
- 기존 NEWSROOM LAB V0.7과 STAT WORKBENCH V1.0을 **각각 복사 보존**하고 별도 ASGI 앱으로 한 서버에 연결합니다.
- `/`는 기존 뉴스룸, `/workbench/`는 기존 통계 분석 도구, `/project1`은 새 통합 점검·오류 훈련 화면입니다.
- 실시간 WebSocket은 **시드 난수 기반 모의 개표**를 전달하며, 실제 선관위 피드가 아닙니다.
- 로컬 내부 문서 근거 검색은 TF-IDF(문자 2~4 gram)이며 LangChain LLM RAG로 표현하지 않습니다.
- 외부 원자료 CSV는 사용자 업로드·해시·중복검사 후 메모리에 보관; 공식성 검증·원본 영구 보존은 별도 과제입니다.
- 데이터는 `simulation`, `user_uploaded_final`, `synthetic_final_sample` 모드로 구분; 합산하거나 실제 당일 실시간 데이터로 표기하지 않습니다.

## 데이터 흐름
1. **모의 방송**: `newsroom/engine.generate` → `evolve` → `/ws` → 기존 뉴스룸, 프로젝트1 대시보드 → ON AIR 교육용 방송상황실(가상 후보·시도·티커). 같은 WebSocket 스냅샷을 사용하고 추가 공식 피드는 연결하지 않습니다.
2. **통계 연계**: (사용자 제공 최종 CSV 또는 교육용 최종 CSV) → `official_results.parse_csv` → `official_store` → 통합 운영실 선거 전용 분석 6종; 모의 WebSocket 자료는 별도 모의 분석 4종. 필요시 `transfer-final-result` → Workbench DATASETS → 전체 17종 사용.
3. **근거 문서**: `mock_documents.json` → TF-IDF 희소 벡터 유사도 → 문서 ID·발행자·발행시각 반환 (수치 외부 검증 아님).
4. **기사**: `evidence_for` → `draft_from_evidence` → `validate_draft` → 사람의 수동 검토·사유 입력 → 통과시 로컬 교육용 승인.
5. **카오스 훈련**: 지역/표수/근거 ID 1개를 의도적으로 변형 → 규칙 불일치 → HTTP 409 승인 차단 및 SQLite 이벤트 저장.
6. **기준시각 검증**: 새 개표 단계 도착 후 이전 단계 기사 승인 요청 → HTTP 409.

## 권한·품질·운영 한계
- 사용자 인증이나 실제 송출 권한 관리가 없으므로 127.0.0.1에서만 실행하세요.
- 승인 상태/기사 원문은 기존 뉴스룸 메모리에만 남고 재시작 시 초기화됩니다. **새 프로젝트1 훈련 이벤트만 SQLite에 지속**됩니다.
- 원자료 자동 수집·원본 영구 저장·공식 데이터 대조, LangChain+LLM 보도 생성, 인증된 승인·정정 절차, 20분 MP4는 완료되지 않았습니다.
- CSV 원본이 사용자 제공이라고 해서 검증된 공식 원본으로 처리하지 않습니다.

## 테스트 대상
- 기존 뉴스룸 60개, 기존 통계툴 44개, 신규 프로젝트1 17개 자동 테스트를 각각 실행합니다.
- 브라우저 로컬호스트 접속은 테스트 환경에서 차단되므로, 제공 화면 이미지는 테스트클라이언트 응답을 브라우저 DOM에 주입한 **오프라인 표시 점검**입니다. 사용자 Windows 실제 접속 시험은 남아 있습니다.
