# Election Newsroom V1.1 — 선거에 필요한 통계기법 선별표

목적: 원본 뉴스룸·공통 통계 워크벤치 소스와 UI를 보존하면서 프로젝트 1 통합 화면에 선거 개표·근거보도에 적합한 기법만 표시한다.

| 범위 | 기법 ID | 화면에 보이는 분석 | 계산 근거 | 해석 제한 |
|---|---|---|---|---|
| 난수 모의 개표 | `live_vote_share` | 후보별 현재 득표율 | 기존 NEWSROOM `analytics.analyze` | 실제 개표와 무관 |
| 난수 모의 개표 | `live_lead_margin` | 선거구 1·2위 격차 | 동일 선거구 후보 득표율 | 잠정 단계이며 당선 예측 아님 |
| 난수 모의 개표 | `live_candidate_trend` | 단계별 후보 누적 표수 | 모의 WebSocket 스냅샷 이력 | 실제 역사적 개표 추이가 아님 |
| 난수 모의 개표 | `live_increment_trend` | 직전 단계 대비 추가 집계 | 모의 단계 사이 표수 차분 | 뉴스룸 재시작 시 이력 초기화 |
| 최종 결과 CSV | `final_district_votes` | 선거구별 후보 득표 합계 | 기존 `official_results.analyze` | 투표율이 아닌 후보 득표수 합계 |
| 최종 결과 CSV | `final_candidate_share` | 개별 선거구 후보 득표율 | 해당 선거구 후보표 합계 분모 | **시도+선거구 지정 필수**, 다른 선거구 합산 금지 |
| 최종 결과 CSV | `final_lead_margin` | 선거구별 1·2위 격차 | 같은 선거구 1·2위 득표율 차(%p) | 단독 후보·0표는 계산 불가 |
| 최종 결과 CSV | `final_close_races` | 근소 격차 선거구 | 격차(%p) 오름차순 | 최종 CSV로 중간 개표 격차 추정 불가 |
| 최종 결과 CSV | `final_region_votes` | 시도별 집계 표수 | 지역별 후보표 합계 | 정당 지지도·투표율 아님 |
| 최종 결과 CSV | `final_vote_distribution` | 선거구별 표수 분포 | 선거구 표수 합계의 구간별 빈도 | 인구 규모 차이에 영향 받음 |

## 적용 제외 및 보존

- 실제 투표율: 투표자 수와 선거인 수, 동일 범위·기준시각이 모두 있어야 계산 가능. 지금은 계산하지 않는다.
- 실제 개표율: 개표 완료 수와 해당 범위의 개표 대상 총수가 모두 있어야 산출 가능. 선거인 수(`target_voters`)는 해당 분모와 같다고 볼 수 없으므로 대체하지 않는다.
- 선거 예측·여론조사 오차·회귀·군집·PCA·부트스트랩: 개표 속보의 기본 근거 통계로 채택하지 않는다. 공통 워크벤치 원래의 17개 기법은 `/workbench/`에서 계속 사용 가능하다.
- 사용자 업로드에 공식 출처 URL이 적혀 있어도 독립 교차검증 이전에는 **공식 확인 데이터**라고 표시하지 않는다.
- 모의 개표 WebSocket 및 사용자 업로드 최종 결과 CSV는 물리적·논리적으로 별개의 데이터 흐름이다.
- 실제 공식 실시간 피드, LangChain+LLM 생성형 RAG, 인증된 편집자 승인, 신규 영상·CG 제작은 이번 버전에서 구현하지 않는다.
- `/api/project1/election/analyze`는 기존 통계 함수 결과를 반환하고, 분석 이력을 SQLite 훈련 로그에 남긴다. 게시·승인 자동 처리는 수행하지 않는다.

## 테스트 및 범위

회귀 시험: 원본 NEWSROOM 60개, 기존 WORKBENCH 44개, 프로젝트1 17개 = 총 **121개**.
신규 검증: 기법 목록 10개, 원본 17종 유지, 모의 단계 전용 분석, 최종 CSV 선거구 분모 강제, 미검증 출처 안내, 비허용 기법·범위 차단.
Windows 11 사용자 PC 실기기·실제 공식 원본 교차검증은 별도 단계로 남겨둔다.
