# 교재 항목별 시스템 적용 분석표 V0.5

기준: 첨부 PDF 《크롤링으로 학습 데이터 만들기》 22쪽.

| 교재 흐름 | 교재 기준 | V0.5 처리 | 검증/한계 |
|---|---|---|---|
| 우선 수집 경로 | 파일 → API → 크롤링 → 정보공개청구(4쪽) | CSV/HTML 업로드. 외부 네트워크 수집 비활성 | 실제 사이트 다운로드/API 미연결 |
| 크롤러 구조 | 요청 → 해석 → 선택 → 저장(9쪽) | 로컬 HTML `press-item` 파싱 | 실 사이트 셀렉터와 무관 |
| 합법적 수집 | robots/약관/공공누리/서버 예절(10쪽) | 출처·권리 확인 문서와 UI 동의 | 실제 이용 조건은 사용자가 확인 |
| 정제 | 공백·중복 제거, 200~2,500자(18쪽) | 적용 | 12중 통과10/제외2 |
| 기사 리드 초안 | GPT 초안 후 사람 검수(20쪽) | API키 없이 규칙 기반 첫 문장 초안 | 모델 호출은 미실행 |
| 저장 | Alpaca `instruction,input,output`(19,21쪽) | 미검수 JSONL + 검수 게이트 JSONL | 10개는 학습 완성 데이터가 아님 |
| 확장 목표 | 100쌍 이상(2,22쪽) | 10개 샘플, 재수집 절차 설계 | 목표 미달 · 실제 출처 수집 필요 |

## 실제 사이트 적용 체크리스트

- [ ] 공식 자료의 URL/발행기관/작성일/수집일/저작권/공공누리 확인
- [ ] API·CSV 우선 및 수집 범위 결정
- [ ] 수집 요청 간격·403/429 정책 준수, robots 확인
- [ ] 200~2,500자 정제, 중복·결측·수집 실패 로그
- [ ] 원문과 기사 리드 수치·날짜·지역 재검증
- [ ] 다른 팀원이 검토하고 `approved` 표시
- [ ] 검수된 100건 이상을 모으면 원본·검수·학습 데이터를 분리
- [ ] 모델 학습 전 이용권한·평가용 테스트셋·편향 검사
